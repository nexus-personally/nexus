## 1. 项目简介

港雀是 NEXUS 内的麻将系统，挂在 `/mahjong/` 路径下。它结合 React + TypeScript 界面、Three.js 牌桌、TypeScript 麻将规则核心、Node/Fastify 服务、WebSocket 在线房间、PostgreSQL 帐号与妈币账本，以及可安装的 PWA。当前可以登录后玩单机、在线朋友房或手机热点面对面无网房。

系统面向横屏手机，也可在桌面浏览器使用。游戏目前提供四人港式玩法，以及按项目选定规则实现的马来西亚三人玩法；三人局与四人局的牌组、番数和结算不同。

## 5. 已实现功能

### 5.1 登录、帐号与游戏入口

- 必须登录后才能开始单机或进入朋友房。
- 注册资料：登录名、显示用户名、密码。
- 登录名为 3–24 位英文字母、数字或下划线；用户名为 1–20 字；密码至少 8 位（上限 128 位）。
- 登录、修改显示名、修改密码、忘记密码（只用登录名定位帐号）。
- 密码以 Node `scrypt` 摘要保存；登录会话用随机 token，数据库只保存 token 的 SHA-256 摘要。
- 账号、显示名和妈币会显示于登录后界面；可退出登录。
- 未配置 PostgreSQL 的本地开发模式使用 `apps/mahjong/server/data/accounts.json`，此目录已排除于 Git。

**安全限制：**忘记密码只验证登录名，没有邮箱、手机、验证码或恢复码。此流程符合当前选择，但任何知道他人登录名的人都可能重设其密码，不适合存放敏感资料。

### 5.2 游戏模式与房间

- 单机对战：本人对电脑，电脑会自动摸牌、应牌、出牌；牌局可存于浏览器 `localStorage` 并尝试继续上次牌局。
- 在线朋友房：建立 3/4 人房并分享 8 位房间码；朋友加入后由空座电脑补位；需互联网和在线服务。
- 面对面无网房：全部手机事先安装/缓存 PWA，连接同一热点，通过扫码或复制配对文字交换 WebRTC 配对资料；可混用 iPhone/Android；每位朋友各配对一次；空座由电脑补位。
- 房主可开始游戏。牌局开始后不允许新玩家加入；房主可取消本局回到房间，让朋友加入再重开；被取消本局的分数不计入结算。
- 只有房主能取消当前局或开始下一局；非房主显示等待房主的状态。
- 在线玩家掉线后，服务可以由电脑接替行动；客户端重连后可回房间查看状态。
- 在线及面对面房间的真人应牌与出牌均限时 15 秒；应牌超时自动过，出牌超时直接打出系统建议牌，不自动胡或杠。单机玩家不设思考时限。
- 同一玩家已处于房间时不能另建/加入其他房间。

### 5.3 牌桌与麻将操作

- Three.js 真实 3D 牌桌和麻将模型，包括牌墙、本人及其他玩家手牌、弃牌河、吃碰杠牌、花牌与桌面庄家/圈局信息。
- 牌墙数据由引擎剩余牌决定；牌墙沿场边呈现，按上下层交替移除。补花、杠后补牌由补牌流程从剩余牌墙取牌。
- 牌桌显示剩余牌数量；玩家手牌立起并可点选；电脑手牌隐藏牌面。
- 支持摸牌、出牌、吃、碰、明/暗/加杠、胡、自摸、过、推荐出牌、花牌补牌。
- 吃、碰采用两阶段选择：每次新的应牌机会先显示「吃／碰／过」动作按钮，玩家选择吃或碰后，才在手牌上方打开完整三张牌组合；即使只有一种合法组合也会打开选择器。普通牌组合排在含飛组合之前，牌友打出的来牌以金框和轻微抬起标示。
- 三种或以上合法组合使用横向滚动列表并从第一组开始排列；滚动轨道保留左右内边距，第一组不会被居中布局裁切。
- 在线及无网朋友牌局提交应牌后会显示所选组合和等待状态；倒数结束前可撤回并改为过牌。应牌倒数结束时自动过牌，出牌倒数结束时自动打出引擎建议牌。
- 多人同时应牌按「胡 > 实牌杠 > 实牌碰 > 飛碰 > 吃」处理；同级由出牌者之后最近的座位优先。实牌碰玩家撤回后，仍有效的飛碰玩家可递补取得该牌。
- 最新弃牌有脉冲光影；轮到自己出牌或可以应牌时显示提示，合法动作按钮带强调状态。
- 牌友手牌/牌墙位置随玩家视角排列；当前 3 人局左侧留空，牌友 1 在右侧、牌友 2 在上方。
- 牌局结束时显示胡牌番型、本局得分、整圈结束状态，并由房主控制下一局。

### 5.4 当前牌组和规则

| 模式         | 牌数与组成                                                                                  | 最低胡番/上限       |
| ------------ | ------------------------------------------------------------------------------------------- | ------------------- |
| 四人港式     | 148 张：原港式 144 张 + 4 张「飛」                                                          | 3 番起胡，13 番封顶 |
| 马来西亚三人 | 84 张：36 筒子（1–9 各四张）、28 字牌（东南西北中发白各四张）、8 花季、4 动物、4 人头、4 飛 | 5 番起胡；原始 10 番起爆番 ×2 |

三人局没有万子、索子；座风相对庄家为东、南、北。庄家赢或庄家流局听牌时继续做庄；其他情况轮庄；目前牌局推进东圈与南圈。

**「飛」百搭**

- 4 人局与 3 人局均有 4 张飛。
- 手中的飛可代替一张数牌/字牌，用于顺子、刻子、将眼。
- 飛牌必须留在手牌中，不能作为弃牌打到牌河；规则核心、玩家操作、电脑出牌、建议出牌和超时自动出牌均排除飛。
- 飞牌不可组成杠；含飛的碰牌之后也不能加杠；三张飛不能自行组成刻子。
- 同时具备两张同牌和一张同牌加飛的碰牌条件时，界面分别显示所用手牌，由玩家选择。
- 飞牌本身不另加番；当前没有“四飞特别胡法”。
- 三人局清一色、混一色、对对胡、平胡（筒眼）、三元牌/风牌组合、七对、九莲宝灯等按规则核心计算；花季、动物、人头按内置条件计番。原始番数达到 10 番即为爆番，结算值为 `原始番数 × 2`，例如 39 番结算为 78；不设二爆、三爆。
- 四人局保留当前实现：自摸、门清自摸、无花、正花/正季、清一色/混一色、对对胡、四杠、大小三元、大小四喜、字一色、清么九、三元刻、门风/圈风等；3 番起胡、13 番封顶。
- UI 说明以分页卡片和实际牌面举例，分开三人/四人说明；普通牌使用本地 SVG，马来西亚动物牌、人头牌和飛牌使用共享透明 PNG 图集。
- 特殊牌面素材：`a1–a4` 为四种动物图样，`h1–h4` 共用同一人头牌图样，`x1` 为紅色「飛」牌面。3D 牌和规则示例均读取 `apps/mahjong/public/assets/tiles/malaysian-special-tiles.png`，图集区域由 `apps/mahjong/src/specialTiles.ts` 定义，避免玩法说明与牌桌出现不同图样。
- 图集是以 Wikimedia Commons 的 `Mala tiles.png` 为来源，经 AI 辅助抠图、清理及重新排版的改编素材，依 CC BY-SA 4.0 发布；署名和来源记录在 [`SPECIAL_TILES_SOURCE.md`](../apps/mahjong/public/assets/tiles/SPECIAL_TILES_SOURCE.md)。旧版 `a1–a4`、`h1–h4`、`x1` 占位 SVG 已移除。

**妈币付款**

- 每个新帐号初始 500 妈币；牌局界面和房间帐号信息展示余额。
- 在线房内真人胜负会按本局净付款增加/扣减；电脑玩家不发生帐号转账。
- 四人局：放铳者支付赢家最终番数；自摸时每位其他玩家各支付最终番数。
- 三人局：放铳时放铳者支付 2 倍、另一名对手付 1 倍；自摸时两名对手各付 2 倍。未爆番时每单位等于实际番数；原始番数达到 10 番时，每单位按原始番数 ×2 计算。
- 线上朋友房的妈币余额最低为 0。输家应付金额超过现有余额时，只扣至 0；赢家只收到其他真人玩家实际支付成功的妈币，电脑席位不会产生妈币。
- 线上房由服务器根据已结束的牌局为仍在房间内的真人帐号生成零和妈币结算，客户端不能自行提交增减金额。
- 面对面无网房仍显示本局分数，暂不写入线上妈币。线上房以开局时的真人帐号为本局结算对象；主动离开后由电脑接管，但该帐号仍承担本局输赢。
- 单机分数不会转为账号妈币。

### 5.5 手机、离线与音效

- PWA 名称「港雀」，支持添加到主画面；manifest 设置 landscape 和 fullscreen；登录资料的本机缓存与静态游戏资源可离线打开。
- 手机上的竖屏会显示横屏提示并尝试锁定方向；按钮尝试全屏/横屏。浏览器是否允许自动旋转或完全隐藏系统栏，取决于浏览器/安装方式/Android 厂商系统。
- 离线静态资源由 Service Worker 版本缓存；注册、重设密码、改资料、线上房间和帐号同步仍须互联网。
- 四种情境配乐（大厅、一般牌局、紧张、结算）有读取 mp3 的能力；当前仓库没有配乐 mp3，所以实际使用 Web Audio 合成旋律。摸牌、出牌、按钮、轮到、吃碰杠胡等音效目前也以合成为主。
- 背景音乐开关只控制 BGM；总静音、麻将音效、语音有独立控制；普通话为默认，支持普通话/粤语/英语/关闭语音选择。
- 当前仓库包含普通话「吃、碰、杠、胡、自摸」5 个语音 MP3；粤语和英语目前走浏览器 `speechSynthesis`。设备语音的发音人、音质和是否可用由操作系统/浏览器决定。

## 6. 数据与部署说明

### PostgreSQL 表

服务启动时建立/调整下列表（环境有 `DATABASE_URL` 时）：

| 表                      | 用途                                              |
| ----------------------- | ------------------------------------------------- |
| `mahjong_accounts`      | 登录名、显示名、scrypt 密码摘要、妈币余额         |
| `mahjong_sessions`      | 登录 session token 的 SHA-256 摘要和所属帐号      |
| `mahjong_wallet_events` | 妈币变更事件；以 `(account_id,event_id)` 防止重放 |

Render 的 `nexus` Web Service 通过 `render.yaml` 连接现有 `nexus-db`。不用另外建立麻将数据库。房间内容、牌局状态、在线 WebSocket socket、AI 计时器不在数据库内。

### 线上数据边界

- 本机 JSON 帐号与线上 PostgreSQL 帐号彼此独立。
- 线上房结算直接由服务器根据当局结果写入账本；旧版 `/mahjong/api/wallet/sync` 返回 HTTP 410，不能再提交客户端 `delta`。
- 无网房没有可被线上服务器独立验证的牌局记录，因此本地分数不会转换为线上妈币。妈币仍是娱乐积分，不是现金。
- PostgreSQL 的运行时建表与新增列是启动期自动处理；目前没有独立版本化的麻将 migration 文件。

## 8. 尚未完成 / 已知限制

### 发布和联机稳定性

1. **在线房间不持久化**：Render 重启、部署或实例替换会结束当前房间和牌局；无法从数据库恢复对局。
2. **单实例内存房间**：没有 Redis/共享状态层；多实例扩容、故障转移及跨实例 WebSocket 房间目前不可用。
3. **无网需实体设备验证**：WebRTC 直连、热点客户端隔离、浏览器后台冻结、电量优化、相机扫码、iPhone/Android 混用尚未实机逐项验收。房主应用关闭/暂停过久会中断整桌。
4. **无网主机无恢复机制**：房主手机丢失、重载页面或离开热点时，没有换主或从快照继续牌局的功能。
5. **无网本地缓存的账户约束**：首次使用前需要上网登录并缓存资源；无网创建/重置账号和线上同步不可用。

### 规则与帐号/经济

6. **候场座位改为中性席号**：开局前随机庄家尚未确定；候场房现在显示席号，开局后牌桌按当前庄家显示三人东、南、北或四人东、南、西、北。不同庄家和轮庄后的实机视觉仍需继续验收。
7. **规则覆盖范围仍有限**：香港麻将与马来西亚三人玩法有地方和家规差异；目前只实现代码及说明列出的番型/付款约定，不是完整规则编辑器，也没有让房主自定义番表或买马/抢杠等完整可配置选项。
8. **说明卡片和计分代码需持续校准**：说明卡片为便于理解的示例；逐项组合番、百搭、暴番封顶及花季番尚未由自动化规则测试全面比对；“当前参考番数”刻意是简化预估，并非完整胡牌结算承诺。
9. **忘记密码安全性低**：只验证登录名。密码重置不会要求旧密码、邮箱/手机验证码或恢复码。
10. **旧版妈币账本需核对**：此前客户端可提交任意 `delta`，且赢家正负号曾算错；修复不会自动识别或回补已有错误账本。无网局暂不转入线上余额。
11. **账号和余额缺少管理界面**：没有管理员封禁、举报、反作弊审计、钱包交易明细 UI 或余额申诉流程。

### 可用性和性能

12. **自动化测试尚未建立**：目前没有麻将引擎单元测试、回归测试、浏览器 E2E 或数据库迁移测试；本次 `npm test` 只是空跑成功。
13. **实机视觉检查待做**：手牌/弃牌可读性、横屏不同宽高比、花牌与手牌碰撞、按钮点击热区、Android 导航栏及 iOS 安装体验应在实际设备上检查。
14. **Three.js 包体与低端机性能**：当前 TileModel chunk 约 539 KB；桌面阴影贴图为 2048×2048，设备像素比最多 2.5，可能增加初次载入、GPU 内存和发热。
15. **音频依赖设备能力**：浏览器要求用户手势解锁 AudioContext；离线时的 mp3 缓存虽跟随静态资源，但实际不同平台语音合成声音不一致。
16. **线上账号迁移/跨环境**：本地 JSON 帐号不会自动迁移到 Render PostgreSQL；目前没有自助导入/迁移工具。

## 9. 建议增强顺序

### P0：可靠性和正确性

1. 为规则核心添加可重放的单元测试：牌组数量、洗牌/发牌、墙牌上下层顺序、3/4 人座风、胡牌牌形、飛替代限制、最低番/封顶、流局听牌、庄家轮转、妈币付款与取消局不结算。
2. 对照三人候场席号和牌桌风位，覆盖不同随机庄家及每一局轮庄后的显示。
3. 核对旧版线上妈币账本，建立交易历史与人工申诉/纠正流程；若未来要将无网局计入线上余额，先定义跨手机共同确认与防伪机制。
4. 做 iOS/Android 热点实机测试矩阵：建立/加入、双向扫码、复制文字、混合系统、电脑补位、掉线恢复、后台/锁屏、房主取消并重新开局。

### P1：线上和离线韧性

5. 若需要部署期间保留牌局，建立持久化游戏快照/事件日志及有版本的数据库 migrations；为断线和服务重启制定重连/恢复策略。
6. 若要扩展 Render 实例或高可用，抽出 Redis/持久化房间协调、WebSocket 广播和选主机制；否则明确固定单实例并加入健康/重启提示。
7. 为离线主机提供明确的断线超时、暂停/恢复、保存房间状态和失败后提示；先确认手机浏览器后台运行限制能否满足体验。

### P2：体验与可维护性

8. 拆分 Three.js chunk、按设备能力调节像素比/阴影，并检查低端 Android 的帧率、发热与下载量。
9. 继续扩充“目前成立番数”的候选出牌分析；补花／杠后补牌的即时自摸加番必须与稳定番数分开显示，并持续以自动化测试校准说明与计分核心。
10. 为线上房间增加玩家准备/房主启动确认、掉线状态、重连计时、旁观者/邀请控制等（按产品需要排序）。
11. 增加账号恢复选项、密码更改后的会话管理、登录尝试保护和管理员工具。
12. 添加回合/结算记录、妈币交易明细与整圈成绩统计；当前账号只看到余额与本局结算。
13. 增加可访问性和多设备视觉验收：键盘/屏幕阅读器、按钮触控面积、文字缩放、色彩对比、横屏安全区与可折叠手机布局。

## 10. 建议视为验收基线的产品承诺

- 没登录不能开始单机或朋友牌局。
- 三人局和四人局牌数、规则说明、番数门槛必须彼此一致。
- 每次摸牌，桌面牌墙真实减少正确的一张；顺序按墙牌顶/底及轮转规则，而不是从玩家自己面前随意抽取。
- 3 人局的座位风位按当前庄家和局数变化；视觉席位与显示风位吻合。
- 最新未被取走的弃牌明确高亮；如果被吃/碰/杠而牌局继续，之后由下一张新弃牌成为最新牌。
- 吃、碰、杠、胡等仅在可操作时显著提示；轮到本人时在桌面和可操作区域都清楚显示。
- 牌局取消不写入正式牌局/妈币结果；只有房主可取消、开局或继续下一局。
- 手机 PWA 断网可打开已缓存资源并加入同热点房；明确展示设备/热点不支持直连时的恢复办法。
- 妈币为虚拟娱乐积分；目前只有线上房服务端结算，不能包装成真实货币或可兑换资产。

# 港雀功能检查报告

> 检查日期：2026-09-30  
> 对照文件：[项目规格与完成度盘点](MAHJONG_PROJECT_SPEC.md)  
> 范围：当前仓库的麻将规则核心、三维桌面、帐号与妈币、线上/无网房间、说明页和构建。以下只把已经由代码或隔离运行场景证实的情况写成「确认问题」；实体手机、Render 数据库与跨设备热点没有在本次检查中实测。

## 检查结论

**有问题，且有一项会直接算错妈币。** 发牌、摸牌、房主权限和基本牌局操作能运行；但真人胡牌的妈币正负号错误，当前余额又允许客户端自行提交增减值，因此不能把现有余额当作可信结算。三人局说明/候场风位、爆番显示也与实际规则核心不一致。

## 已确认问题

| 优先级 | 问题与复现条件 | 代码依据 | 建议处理 |
| --- | --- | --- | --- |
| P0 | **真人赢家的妈币会扣钱。** `mamoneyDelta` 在赢家分支把其他真人玩家的负数付款相加。例如三人局付款 `[+40, -20, -20]`、第三席为电脑时，赢家应从真人对手收 `+20`，实际计算为 `-20`；真人输家也扣 `-20`，两人余额同时减少。 | `apps/mahjong/src/app.tsx` 的 `mamoneyDelta`（约 18–25 行）及结算提交（约 115–135 行） | 赢家应取其他真人付款之和的相反数；以双真人加电脑、三真人、四真人以及自摸/放铳场景核对每局真人余额合计为零。已错误记账的线上数据需要先核查账本，不能单靠改代码自动恢复。 |
| P0 | **客户端能伪造妈币。** 已在独立本地 API 中以普通已登录帐号提交虚构 `eventId` 和 `delta: 99`，余额由 507 变成 606。唯一事件 ID 只防止同一事件重复入账，不能证明该结算来自真实牌局。 | `apps/mahjong/server/index.mjs` 的 `/api/wallet/sync`（约 120–146 行） | 由线上房间主机根据已完成牌局直接生成各帐号的结算事件；客户端仅查询结果。无网结算另定可信边界。 |
| P1 | **三人局风位文案冲突。** 规则核心把庄家相对席位映射为「东、南、北」，说明页写「东、南、西」，候场房对第三席也固定显示「西」。四人候场风位也固定按席次显示，开局随机庄家后可能与实际座风不同。 | `apps/mahjong/src/engine.ts` 的 `seatWindIndex`（约 28–32 行）、`guide.tsx`（约 26 行）、`rooms.tsx`（约 134 行） | 统一说明和候场席位的含义：若显示当前风位，就按当前庄家动态计算；开局前尚无庄家时用「席位 1/2/3」等中性标签。 |
| P1 | **三人爆番明细相加超过实际番数。** 三人结算在已有条目达 10 番时又追加「爆番 +10」，随后把付款番数封顶为 10。可出现明细合计 20 或 24 番、标题/付款却是 10 番。隔离规则场景已得到 `raw=24`、`fan=10`。 | `apps/mahjong/src/engine.ts` 的 `scoreResolved`（约 284 行）和 `evaluateWin`（约 320–325 行），`app.tsx` 结算明细（约 282 行） | 「爆番」应是封顶状态标记或替代结算项，不应再作为额外的 `+10` 番计入原始总番。结算页分别展示原始番数与实际支付番数。 |
| P1 | **掉线电脑代打时可能出现单边妈币结算。** 在线/无网主机在已占用的人类席位断线后让电脑接手，但该玩家的 `player.ai` 保持 `false`。其他在线玩家结算时仍会把此席位当真人计入转账；无网断线手机无法在进行中的局重新配对以接收该结算。 | `apps/mahjong/server/index.mjs` 的 `schedule`、开局 `player.ai` 设置（约 188–210、269–272 行）；`offline-room.ts` 的 `invite`、断线处理和 `schedule`（约 100、130–132、200–212 行）；`app.tsx` 的 `mamoneyDelta` | 明确断线代打期间是否仍计本人妈币；若计入，需服务端/房主可靠地记录双方账本并支持断线后领取；若不计入，结算时按行动主体而非开局时的 `ai` 标记判断。 |
| P2 | **朋友长时间不操作可让房间停住。** 在线与无网房在有已连接真人需要应牌时直接等待其选择，没有倒数或自动「过」；轮到已连接真人出牌时也没有超时动作。房主虽能取消局，但无法继续当前局。 | `apps/mahjong/server/index.mjs` 的 `schedule`（约 188–210 行）；`offline-room.ts` 的 `schedule`（约 197–216 行） | 设计回合/应牌倒数与断线判定，超时自动过牌或由电脑接管，并在 UI 显示剩余时间。 |

## 尚未证实或尚未覆盖

- 没有用真实 Android/iPhone 验证横屏、全屏、字体/牌面清晰度、触控位置、相机权限和系统安全区。浏览器模拟不能代替实机。
- 没有以两部以上手机在断网热点测试 WebRTC 建房、混合 iPhone/Android、后台冻结、重连和房主退出。
- 没有连接或修改 Render 生产 PostgreSQL；线上历史妈币是否已经出现错误余额，需要先用账本核对。既有资料不可凭本次隔离环境推断。
- 尚无可持续运行的引擎单元测试、API 集成测试和浏览器端到端测试；这次的动态检查为一次性隔离场景。
- 现有忘记密码只凭登录名可改密码，虽符合此前需求，但任何知道登录名的人都可能接管帐号；在正式公开使用前需另定恢复方式。

## 修复进度（当前版本）

- **赢家妈币正负号、客户端伪造结算：**线上房改由服务端读取已经完成的牌局，按仍在线的真人帐号计算零和转账并写入账本。旧版客户端上传 `delta` 的接口现在返回 HTTP 410。隔离场景的 `[+40, -20, -20]`、第三席电脑，现计算真人变动 `[+20, -20, 0]`；虚构 `+99` 请求被拒绝，帐号仍为 500。
- **风位与爆番：**三人说明改为东、南、北；候场房显示中性席号，开局后牌桌使用实际庄家相对风位。爆番采用单一级别：原始番数达到 10 番时，统一按 `10 × 2 = 20` 的结算值付款；结算页分别显示原始番数、爆番倍数和结算值，不设二爆、三爆。
- **断线代打与等待：**线上结算只包括结算时仍在线的真人；无网局只保留本局分数，不再向线上帐号上传未经验证的金额。线上/无网房加入应牌 15 秒、出牌 60 秒倒数，超时自动过牌或由房间主机代行动。
- **取消边界：**已完成并结算的牌局不能再按「取消本局」抹掉结果；房主可按下一局继续。未结算牌局仍可取消。
- **飛牌碰杠与应牌选择：**飛不能用于杠，也不能将含飛的碰牌再加杠；同时满足普通对子碰与对子加飛碰时，界面分别列出用牌组合供玩家选择，避免显示两个内容相同的「碰」。
- **吃碰选择体验与竞争处理：**吃、碰按钮改为两阶段选择器，使用完整三张牌展示每个合法组合；普通牌组合先于飛组合，来牌有金框和抬起提示。在线及无网房支持提交后等待和撤回；服务器与离线房主按「胡 > 实牌杠 > 实牌碰 > 飛碰 > 吃」、同级按距离出牌者最近的座位裁定。撤回会把该玩家的选择改为过牌，让下一名仍有效的玩家递补。
- **飛不可弃出：**规则核心拒绝将 `x1` 打入牌河；玩家不能从可访问手牌按钮选择飛，点击 3D 飛牌会显示规则提示，出牌按钮也会保持不可用。电脑、建议出牌及线上／无网超时自动出牌统一只从非飛手牌选择。
- **应牌显示顺序和横向滚动：**每次新应牌先回到「吃／碰／过」第一层，只有选择动作后才显示组合。三组或以上组合改为从左侧第一组开始排列，并加入完整滚动轨道和左右留白，避免第一组被居中溢出裁切。
- **特殊牌面素材：**`a1–a4` 动物牌、`h1–h4` 人头牌及 `x1` 飛牌现使用同一透明 PNG 图集；3D 牌桌与玩法说明读取相同区域定义。旧占位 SVG 已移除，素材来源与 CC BY-SA 4.0 署名已记录于 `apps/mahjong/public/assets/tiles/SPECIAL_TILES_SOURCE.md`。

以上改动已通过 `npm run build --workspace @nexus/mahjong`。修复仍需真实手机与 Render 环境验收；本次没有改写线上旧账。

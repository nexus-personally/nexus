# 港雀麻将：当前实现功能规格

> 基线日期：2026-10-05<br>
> 规格性质：以当前仓库代码为准的产品、规则、接口与验收基线<br>
> 项目路径：`apps/mahjong`<br>
> 线上入口：<https://nexus-2rwr.onrender.com/mahjong/>

本文记录港雀麻将截至基线日期已经实现的功能、数据边界、已知限制及验收要求。尚未落地的想法只列在“后续建议”，不视为当前功能承诺。历史审计见 [MAHJONG_FUNCTION_AUDIT.md](MAHJONG_FUNCTION_AUDIT.md)。

## 1. 产品范围

港雀是 NEXUS System 02 下的横屏麻将游戏，支持：

- 单机人机对战；
- 有互联网的线上朋友房；
- 同一热点内、不依赖麻将服务器转发牌局的 WebRTC 无网房；
- 三人马来西亚麻将与四人港式麻将；
- 帐号、妈币、在线状态、聊天、语音、音效、PWA 与多屏幕响应式体验。

项目以横屏为主要使用方式。桌面、平板、折叠屏和手机横屏均共享同一套游戏能力，版式按可用宽高缩放；手机竖屏显示旋转提示。

## 2. 技术架构与运行边界

| 层级 | 当前实现 | 主要位置 |
| --- | --- | --- |
| 前端 | React 19、TypeScript、Vite | `apps/mahjong/src/` |
| 3D 牌桌 | Three.js、3D 手牌/牌墙/弃牌/副露 | `apps/mahjong/src/table3d/` |
| 规则核心 | 与 UI 分离的 TypeScript 状态机、计番、AI | `apps/mahjong/src/engine.ts` |
| 服务端 | Node.js、Fastify、原生 WebSocket | `apps/mahjong/server/index.mjs` |
| 持久化 | 生产使用 Neon PostgreSQL；本地无数据库时退回 JSON | `apps/mahjong/server/` |
| 无网联机 | WebRTC DataChannel、二维码/文字交换 SDP | `offline-room.ts`、`offline-pairing.tsx` |
| 语音 | LiveKit 房间语音 | 客户端房间代码与服务端 token API |
| PWA | manifest、Service Worker、离线静态缓存 | `apps/mahjong/public/` |

数据边界：

- 帐号、session、妈币账本与 `is_online` 存数据库；
- 线上房间、牌局、计时器及 socket 仍在单一 Node 进程内存；服务重启会终止进行中的房间；
- 单机存档保存在当前浏览器；
- 无网房由创建者设备作为权威主机，房主退出或页面被系统冻结时无法自动迁主；
- 无网局和单机局不写入线上妈币。

## 3. 用户与角色

| 角色 | 能力 |
| --- | --- |
| 未登录访客 | 查看入口；注册、登录、重置密码 |
| 已登录玩家 | 单机、建房、加房、修改资料、查看妈币、退出登录 |
| 在线房主 | 选择 3/4 人、分享房码、取消未完成牌局、进入下一局 |
| 房间成员 | 准备、聊天、语音、游戏操作、离开房间 |
| 电脑玩家 | 补足空位、自动摸牌/应牌/弃牌、接管已离线真人席位 |

## 4. 帐号、资料与在线状态

### 4.1 帐号流程

- 注册字段：登录名、显示用户名、密码。
- 登录名：3–24 位英文字母、数字或下划线；用户名：1–20 字；密码：8–128 位。
- 支持登录、退出、修改显示名、以当前密码修改新密码，以及仅凭登录名重置密码。
- 密码使用 scrypt 摘要；Bearer session 使用随机 token，数据库仅保存 SHA-256 摘要。
- API 请求体限制 8 KB；帐号相关请求有每分钟 30 次的进程内限流。
- 新帐号初始妈币为 500。

安全说明：当前“忘记密码”只验证登录名，没有邮箱、手机、验证码或恢复码，不适合承载敏感资产。

### 4.2 在线状态

- `mahjong_accounts.is_online` 让管理员可直接从数据库查看目前在线帐号，不额外提供管理页面。
- WebSocket 鉴权成功后设为 `true`；同一帐号最后一个 socket 断开后设为 `false`。
- 服务启动时先把遗留在线值清为 `false`，避免异常终止造成永久假在线。
- 此字段代表与当前服务进程存在已认证 socket，不等同于正在牌局中。

## 5. 首页与入口流程

- 登录后显示品牌、用户名、妈币，以及全屏、玩法说明、音频控制入口。
- “人机对战”直接建立本地游戏；“玩家对决”进入线上或无网房流程。
- 玩法说明使用覆盖层分页展示三人/四人规则与牌例；帐号条在说明层打开时不会盖住内容。
- 修改资料 dialog 独立响应式布局：标题与关闭键对齐，窄屏和低高度设备不会被裁切。
- 所有主操作有点击防重复/等待状态，房间创建和离开不会因为重复点击产生多个请求。

## 6. 单机模式

- 玩家与 AI 对战，人数依所选三人或四人玩法补足。
- AI 自动完成应牌、摸牌与出牌；玩家没有强制思考倒数。
- 游戏状态可保存至 `localStorage` 并尝试从同一浏览器继续。
- 单机得分只用于本地对局，不增减帐号妈币。

## 7. 线上朋友房

### 7.1 建房与候场

- 可创建 3 人或 4 人房，产生 8 位十六进制房间码。
- 支持复制房码；成员输入房码加入。
- 候场画面显示真人席位、电脑补位、准备状态和房间人数。
- 真人全员准备后自动开局，空位由 AI 补齐；开始后的牌局不接受新成员。
- 房主离开时转移房主；成员离开进行中牌局后由 AI 接管并广播系统消息。
- 同一帐号不能同时建立或加入另一房间。

### 7.2 重连与离开

- 客户端 socket 意外断开后约 800 ms 开始重连，并以帐号恢复房间快照。
- 断线期间 AI 可接管该席位；重连后玩家重新获得当前状态。
- 离开和建房按钮在请求进行期间锁定，避免看似无响应后的重复操作。
- 房主可取消尚未结算的当前局；取消局不写正式比分或妈币账本。

### 7.3 权威模型与隐私

- 服务端验证在线房行动并广播权威快照。
- 对手手牌与未摸牌墙对普通客户端隐藏；结算时才揭示必要资料。
- 每个真人的应牌/弃牌倒数为 15 秒：应牌超时自动过，弃牌超时打出系统建议牌，不自动胡或杠。

## 8. 面对面无网房

- 所有设备先安装或缓存 PWA，再连接同一手机热点。
- 使用 QR code 或复制配对文字交换 WebRTC offer/answer。
- iPhone 与 Android 可以混用，空座由 AI 补位。
- 房主设备运行权威规则并通过 DataChannel 同步状态。
- 无网房不依赖线上 WebSocket维持牌局，但首次安装、帐号注册/重置和线上同步仍需互联网。
- 无网房得分不写入线上妈币；没有主机迁移或崩溃恢复。

## 9. 房间社交功能

### 9.1 聊天与弹幕

- 房间文字消息最长 50 字，每位玩家最短发送间隔 2 秒。
- 服务端/房主保留最近 100 条消息并同步给成员。
- 新消息可显示为弹幕；聊天折叠时显示未读数。
- 玩家可展开历史、隐藏或显示弹幕，偏好保存于 `localStorage`。
- 加入、离开和电脑接管等事件以系统消息显示。

### 9.2 LiveKit 语音

- 支持加入语音、静音/取消静音、离开和当前语音人数显示。
- 服务端按已认证帐号签发短期（约 2 小时）房间 token。
- LiveKit URL/API key/secret 未配置时，界面明确提示不可用，不影响文字房和牌局。

## 10. 游戏状态与操作

### 10.1 状态机

游戏主要阶段为：

1. 发牌、补花；
2. 当前玩家摸牌；
3. 弃牌；
4. 其他玩家应牌；
5. 吃/碰/杠后的继续行动；
6. 胡牌或流局结算；
7. 下一局或整场结束。

支持摸牌、弃牌、吃、碰、明杠、暗杠、加杠、抢杠胡、胡、自摸、过、补花、推荐出牌与取消应牌。

### 10.2 应牌规则

- 动作优先级：胡 > 实牌杠 > 实牌碰 > 飛碰 > 吃；同级按出牌者之后最近座位优先。
- 吃、碰使用两阶段选择：先选动作，再选具体三张组合；只有一组时仍进入组合确认。
- 普通组合排在含飛组合之前；来牌以金框和抬起效果标记。
- 三组以上可以横向滚动，第一组不会被居中裁切。
- 在线/无网玩家提交后显示等待，可在倒数结束前撤回并改为过。
- 真实碰撤回后，仍有效的飛碰申请可递补取得弃牌。

### 10.3 AI

- AI 可判断合法动作、应牌、胡牌和推荐弃牌。
- AI 与超时自动弃牌都不会把飛牌打出。
- 真人断线席位由 AI 暂时接管。

## 11. 三人及四人规则

### 11.1 牌组

| 模式 | 牌数与组成 | 起胡门槛 |
| --- | --- | --- |
| 四人港式 | 152 张：136 基本牌、8 花季、4 动物、4 飛 | 3 番 |
| 马来西亚三人 | 84 张：36 筒、28 字、8 花季、4 动物、4 人头、4 飛 | 5 番 |

- 三人局没有万子、索子；风位依庄家为东、南、北。
- 四人风位为东、南、西、北。
- 牌墙、补花和杠后补牌从真实剩余墙牌推进。
- 当前牌局推进东圈、南圈；庄家赢或庄家流局听牌时连庄，其余情况轮庄。

### 11.2 飛牌

- 飛是手牌百搭，可代替一张数牌或字牌组成顺子、刻子或将眼。
- 飛不能弃出、不能组成杠；三张飛不能自行组成刻子。
- 含飛碰牌不能加杠。
- 玩家摸到被含飛碰牌替代的真牌时，可主动“起飛”：真牌进入副露并取回一张飛。
- 吃牌及含飛杠不适用起飛；飛牌本身不加番，没有“四飛特别胡法”。

### 11.3 计番与付款

- 两种模式原始番数达到 10 时进入爆番：结算番数为原始番数 ×2，不封顶。
- 已实现的番型由引擎统一计算，包括牌型、门清/自摸、花季、动物、人头、风牌/三元牌、杠及三人特定牌型；UI 规则说明必须与引擎保持一致。
- 四人放铳：放铳者支付 2 单位，其余两家各 1 单位；四人自摸：三家各 2 单位。
- 三人放铳：放铳者支付 2 单位，另一家 1 单位；三人自摸：两家各 2 单位。
- 单位值为最终结算番数。

## 12. 妈币与账本

- 新帐号 500 妈币，余额最低为 0。
- 只有线上朋友房的真人帐号参与妈币结算；AI、单机、无网房不参与。
- 服务端根据已结束牌局计算付款，客户端不能提交任意余额增减。
- 输家不足额时最多扣到 0；赢家只收到其他真人实际支付的数额。
- 开局时的真人帐号是该局结算对象，即使中途离开并由 AI 接管仍承担该局输赢。
- 每笔变更写入 `mahjong_wallet_events`，通过 `(account_id, event_id)` 防止重放。
- 旧 `/mahjong/api/wallet/sync` 已停用并返回 HTTP 410。

## 13. 牌桌、视觉、动作字效与音频

### 13.1 3D 牌桌

- 3D 牌墙、手牌、牌河、副露、花牌、当前局/圈、剩余牌数及各家资料。
- 对手手牌背面显示；本人牌可点击选中。
- 最新未被取走的弃牌有脉冲高亮；轮到本人和可应牌状态有明确提示。
- 三人局按本人下方、牌友 1 右侧、牌友 2 上方布局，左侧留空；四人局四边完整显示。

### 13.2 吃碰杠动作字效

- 吃、碰、杠成功时，在实际行动者对应座位显示透明 PNG 动作字，并配合甩入、缩放、回弹、闪光效果与音效。
- 本人动作字位于桌面下方中央但向上偏移，避免遮住自己的手牌；对家位于上方中央；左右玩家分别贴近左右席位。
- 胡与自摸不显示动作字，因为牌局会立即进入结算画面。
- `prefers-reduced-motion` 下减少强烈位移和缩放。

### 13.3 音频

- 大厅、一般牌局、紧张阶段和结算四种音乐场景。
- 总音量、BGM、音效和语音分别控制；BGM 可单独关闭。
- 摸牌、弃牌、按钮、轮到、吃、碰、杠、胡等有音效。
- 普通话为默认语音，支持粤语、英语或关闭；仓库内普通话使用录音，缺少的语言可退回浏览器语音合成。
- 浏览器要求用户手势后才解锁 AudioContext。

## 14. 结算画面

- 结算覆盖牌桌并压暗背景；整体为绿金英雄区加米色双栏账册。
- 最外层使用连续细金框与四角中式角花；金框在整个结算面板最外围，不包在内容栏内部。
- 英雄区包含金色“胡”印章、本局结算标题、获胜说明、总番数、麻将牌装饰背景和“收起”。
- 左栏显示番种逐条明细、每项番数和合计。
- 右栏显示本局输赢：玩家、当局增减、累计分数；本人高亮并显示皇冠，输分使用红色。
- 底部显示分数已计入累计成绩，并提供“继续下一局”。房主可继续，成员等待房主。
- 结算可以收起/恢复，不会销毁牌局结果。
- 三人及四人结果使用对应行数和尺寸；移动端按钮规则：
  - 三人局：`.result-panel .result-next` 为 `width: 100%`、`min-height: min(9.3cqh, 4.1cqw)`、`margin-top: 20px`、`border-radius: 8px`；
  - 四人局：`width: 100%`、`min-height: min(8.3cqh, 4.1cqw)`、`margin-top: 2px`、`border-radius: 8px`。

## 15. 玩法说明与对话框

- 三/四人说明分开，包含牌组、起胡与爆番、飛牌、吃碰杠、补花、付款等分页内容。
- 普通牌使用本地 SVG；马来西亚动物、人头和飛牌使用共享透明 PNG 图集。
- 资料编辑、音频、房间配对及确认类 dialog 使用独立 class 范围，调整不会污染主页或牌桌。
- dialog 支持低高度横屏：缩短间距、允许内部滚动、保持标题/关闭键和主要按钮可触达。

## 16. 响应式与设备要求

### 16.1 目标设备

重点覆盖：

- 桌面 16:9 与宽屏；
- iPad Mini 1024×768 及常见 iPad/Android 平板；
- iPhone 16 Pro Max 横屏 956×440；
- Pixel 9 横屏 924×412；
- Pixel Fold 横屏及窄高比折叠设备；
- iOS Safari 安全区、Dynamic Island 与底部 home indicator。

### 16.2 布局策略

- 游戏外框以可用 viewport 宽高共同计算缩放，不单靠宽度放大，因此 iPad Mini 不会纵向溢出。
- 3D 牌桌限制为最高 30 FPS；移动端像素比最高 1.35、桌面最高 1.5，移动端关闭 WebGL MSAA，阴影贴图为 1024×1024。
- 页面进入后台时暂停 WebGL、GSAP 和音频；结算阶段的被遮挡牌桌改为按状态更新一次，不持续重绘。
- 首页 header 与内容层在低高度设备使用独立缩放/定位，帐号条和圆形工具键不得遮挡说明、房间或 dialog。
- 房间主面板在桌面居中；手机横屏同时做水平与视觉垂直居中，不能偏向左下。
- 候场、牌桌与结算分别设置响应式尺寸，不通过全站 transform 粗暴缩放。
- 使用 `env(safe-area-inset-*)` 保留安全区；触控目标仍保持可点。
- 竖屏显示方向门；横屏不应出现页面级纵向滚动，必须滚动的内容放在面板内部。

## 17. PWA 与离线缓存

- manifest 名称为“港雀”，显示模式为 fullscreen，首选横屏。
- Service Worker 预缓存构建资源，清理旧版本缓存，并为导航提供离线回退。
- 开发环境 Service Worker 不依赖未替换的 `__PRECACHE_FILES__`，避免 `ReferenceError`。
- manifest 必须返回有效 JSON 与正确 MIME，不能出现首列 syntax error。
- 离线可打开已缓存 UI 和本地/热点玩法；帐号服务、在线房、LiveKit 与数据库同步必须联网。

## 18. 服务端接口、消息与数据库契约

### 18.1 HTTP 能力

服务端提供注册、登录、会话读取、资料修改、密码重置、LiveKit token、静态文件与健康检查。具体路径以 `apps/mahjong/server/index.mjs` 为准。

### 18.2 WebSocket 能力

WebSocket 消息覆盖鉴权、建房、加房、准备、离开、取消牌局、游戏动作、聊天、同步与重连。未知或不合法动作由服务端拒绝，不应直接改变权威游戏状态。

### 18.3 PostgreSQL 表

| 表 | 关键用途 |
| --- | --- |
| `mahjong_accounts` | 登录名、显示名、scrypt 密码、`mamoney`、`is_online` |
| `mahjong_sessions` | session token 摘要、帐号、创建/失效时间 |
| `mahjong_wallet_events` | 妈币变更、事件去重、审计 |

麻将服务启动时执行兼容性建表/加列；麻将表目前尚无独立版本化 migration 系统。NEXUS API 的其他数据表使用 `infra/migrations`。本地 JSON 帐号与线上 PostgreSQL 帐号互不自动迁移。

查看当前在线帐号的 SQL 示例：

```sql
SELECT id, login, name, mamoney, is_online
FROM mahjong_accounts
WHERE is_online = TRUE
ORDER BY name;
```

### 18.4 生产部署与数据库基线

## 21. 已知限制

1. 线上房是单实例内存状态，服务重启、部署或多实例路由会丢失对局。
2. 无网房无主机迁移、断线快照恢复及跨设备可信结算。
3. 忘记密码仅凭登录名，安全性不足。
4. `is_online` 是 socket presence，不是严格的“正在操作/正在游戏”状态；异常网络需等待连接关闭才能回落。
5. 规则是项目选定的港式/马来西亚三人规则，不覆盖所有地方家规，也没有房主自定义番表。
6. 复杂百搭牌型、所有抢杠/流局边界仍需继续扩充回归样本。
7. 没有管理员帐号/封禁/举报、妈币交易明细 UI 或余额申诉流程。
8. Three.js 与高清背景在低端手机可能增加下载量、GPU 内存和发热。
9. 浏览器语音合成质量、音色和离线可用性由设备决定。
10. 自动化测试尚未覆盖完整浏览器 E2E、真实 WebRTC 热点、多实例恢复和所有实体设备。
11. Render 免费 Web Service 会休眠；Neon Free 受计算、存储和休眠额度限制，冷启动可能增加首次请求时间。

## 22. 验收基线

- 未登录不能开始单机或朋友房。
- 三人/四人的牌数、风位、起胡门槛、番数和付款与说明一致。
- 飛不可弃、不可杠；AI、推荐牌和超时弃牌也不能选择飛。
- 牌墙每次摸牌/补牌只减少正确的一张，并与 3D 显示同步。
- 最新弃牌、当前回合、可用动作和倒数清楚可辨。
- 同时应牌严格按优先级与座位距离裁决。
- 在线对手隐藏手牌和墙牌，结算才揭示。
- 取消局不计分、不结算妈币；线上妈币只由服务端写入且余额不低于 0。
- 吃碰杠动作字显示在行动者座位；自己和对家均在中轴线上；自己位置不挡手牌；胡/自摸不显示动作字。
- 结算面板金框位于最外围，四角完整，内容不越框；三/四人移动端按钮采用各自尺寸。
- iPhone 16 Pro Max、Pixel 9、Pixel Fold、iPad Mini 和桌面横屏无 header/content/dialog 重叠，无页面级裁切。
- manifest、Service Worker 和离线入口无语法错误；线上功能断网时给出可理解提示。
- 建房、离房、继续下一局等异步按钮不能因重复点击产生重复请求。

3. 完善键盘、屏幕阅读器、文字缩放、色弱与 reduced-motion 验收。
